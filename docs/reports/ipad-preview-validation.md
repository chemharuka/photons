## Scope

The initial revision adds an iPadOS 18+ development preview using the existing Swift/Metal, catalog, panorama, LCC and export modules. UI regression checks verify center and off-center grabs move the geometric center by the same screen delta. Revert restores the last successful layout and immediately re-enables export without a new alignment job.
- The simulator reported current/potential EDR headroom of **1.0 / 1.0**. Generated half-float previews previously had content headroom **0**, and `UIImage(cgImage:)` reported them as SDR. Preview images now carry measured headroom and use a Core Animation surface with explicit dynamic-range selection. The thumbnail cache stores losslessly compressed half-float pixels together with the histogram. Engine checks verify HDR samples above 1, SDR samples at or below 1, different histograms, display-layer mode and cached HDR preservation.
- Reproduced the 6000 px Boston DNG lines in both iPad and macOS decoders. ## Remaining limits

Physical iPad memory, thermals, HDR display headroom, background behaviour and large full-resolution exports remain unverified. The development preview now offers full resolution as well as 2048/4096/6000 px; it checks estimated memory against the process budget before rendering. RAW LCC still reads full mosaics and is expensive in Debug; the interactive local preview uses an optimized Release build. Perspective currently uses planar homographies for modest changes in view, not spherical/360° projection. Correct individual sources before perspective stitching when LCC is needed.

The 43XL calibration is a developer-created user profile. The four approximately 810 MB Boston RAWs are optional local resources and are not committed to Git. The simulator sample build includes them; default Release archives omit them unless explicitly requested. Generated CI fixtures contain no private photographs.

This is scoped verification, not a claim that the repository's full historical acceptance suite passes. The existing upstream PR also has pre-existing integration conflicts with upstream main; these checks validate this branch, not an upstream merge result.

## Panorama brightness follow-up — Boston 628–633

- Added shared scene-linear exposure and hue-preserving HDR-highlight controls below both panorama previews. iPad debounces changes by 100 ms; Mac refreshes on slider release. Both reuse cached source previews and preserve registration, masks, photometric gains and LCC positioning. Controls apply to output, not only the screen, and survive the Mac export-worker snapshot and portable metadata.
- Inspected the original fork's Mac history (`ebecce5`, not a checkout of upstream main). Its shared LCC highlight-protection code chose a global exposure from the 99.5th-percentile RGB peak, reducing the whole image toward 0.9 white. Removed this global darkening in favour of a pixel-local highlight shoulder. Overlap exposure matching already uses robust overlap medians and excludes near-clipped samples; it was not replaced.
- Real B0000628–B0000633 automatic shift registration passed on Mac and iPad; canvas 21,330 × 20,255. The Mac diagnostic's covered-pixel linear RGB-maximum median was 0.07776 before and after default highlight protection. With +1 EV and a 1-stop (2×) highlight ceiling it became 0.15552; the maximum fell from 2.68555 to 1.81348. Two cached preview adjustments together took 0.097 seconds on this host. These are image statistics and a host measurement, not a physical-iPad energy/display benchmark.
- Simulator Release tests: 12 engine tests passed, including the optional six-frame workflow, HDR/SDR histogram changes, brightness metadata, reset, and the existing four-RAW LCC → 6000 px lossless DNG regression.
