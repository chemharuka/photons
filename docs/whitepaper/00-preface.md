# 卷首：这份文档是什么

Photons 是 macOS 上的一个原生 RAW 工作流：导入一个文件夹，挑片，非破坏性显影，然后导出。它自己不带解码器。去马赛克、镜头校正、机器学习降噪都来自 Apple 的 `CIRAWFilter`（`Sources/PhotonsCore/RAWDecoder.swift:1`）。解码之上的整条算术链、蒙版、色彩管理、XMP 与导出，由 Photons 自己的 Metal 渲染图画。

这份文档只讲解码之上的那一半：画面怎么被画到屏幕上、每个参数作用在哪个域、这些参数的具体算法是什么。

## α 阶段声明

项目还在 α。本文写的是当前实现，不是稳定 API，也不是路线图。管线阶段、参数范围、常数都会变。每一页页脚写着构建时的代码基准（`git rev-parse --short HEAD`），正文里每个常数后面跟着 `文件:行`。文档和代码冲突时以代码为准，并把那一处当成文档的 bug。

有几样东西这里不写：界面设计（布局、控件、交互规格）、性能优化计划、与其他软件的评测。文中会出现「面板上的滑杆」这样的说法，那只是参数的名字，不是界面描述。

## 读者

- 想知道「这个滑杆到底动了什么」的高级用户；
- 要评审渲染正确性的工程师；
- 准备改这条管线的未来贡献者。

读之前需要知道：RAW 是线性光，sRGB 是传递函数，跟「颜色」不是一回事，`log2` 也用得惯。没读过 Photons 的代码没关系。

## 三个域，先说清楚

后面每一章都围着这三个域转，先用一张表把它们说清楚：

| 域 | 变量是什么 | 典型操作 | 在管线里的位置 |
|---|---|---|---|
| **RAW 解码域** | 相机原始像素，交给 Apple 的 `RawCamera` 解释 | 去马赛克、色温/色调、机身降噪、镜头校正 | `CIRAWFilter`，渲染图之外 |
| **场景线性域** | 线性光，`1` 是 SDR 白，可以大于 1 | 黑电平、曝光、黑白端点、曲线、去雾、暗角 | S1 到 S1.9 |
| **显示参考域** | 经过色调映射的显示码，`0…1` | 高光/中间调/阴影、对比、饱和、HSL、分级、锐化、颗粒 | S2 之后 |

一条贯穿全文的规则：**一个操作必须待在它的量所在的域里**。把曝光做成显示域增益，被压缩的高光就再也拿不回来；把去雾做成显示域减法，`A = 1` 时高光越去雾越亮（`Sources/PhotonsCore/Stage.swift:56`）。第三、四章的大部分篇幅都在解释这条规则的后果。

## 记法

| 记号 | 含义 |
|---|---|
| `EV` | 以 2 为底的对数曝光，`+1 EV` = 光量 ×2 |
| 显示码 | sRGB 编码后的 `0…255`，`0.5` 约为 18 % 灰的编码值 |
| `Y` | 工作基色（线性 Rec.2020）下的亮度，权重 `0.2627 / 0.6780 / 0.0593`（`Sources/PhotonsCore/ColorPrimaries.swift`） |
| `L` | `log2(Y)`，单位是「相对显示白的 EV」，显示白处 `L = 0` |
| `u` | 曲线的横轴坐标：`0…0.5` 是 SDR 显示码，`0.5…1` 是 `+0…+4 EV`（`Sources/PhotonsCore/HDRCurve.swift:57`） |
| `S0…S4` | 渲染阶段编号；`.5` / `.6` 之类是插在中间的阶段，执行顺序见第 1 章 |
| 键 / key | 阶段缓存的标识串，只由该阶段真正读到的参数组成（第 2.4 节） |

## 术语表

| 术语 | 在这份文档里的意思 |
|---|---|
| **画布（canvas）** | 要画的像素面。屏幕上等于 drawable 的像素尺寸，导出时等于裁切框（`CanvasRole`）；照片在屏幕画布里可以留黑边 |
| **内容像素** | 裁剪后照片自己的像素网格，`RenderOptions.scale` 作用在它上面 |
| **rung** | 解码阶梯上的一档，`0.5` 是预览档，`1.0` 是全分辨率档 |
| **stage** | 渲染图里的一个 pass，输入、输出与缓存键各自独立 |
| **条件 stage** | 只有谓词成立时才存在的阶段（有蒙版、曲线非恒等、颗粒 > 0……） |
| **中性零变化** | 没碰过的参数必须让像素逐字节不变，「看起来一样」不算 |
| **键链（key chain）** | 每个阶段的键 = `H(上一阶段的键 | 本阶段材料)`；链尾相等蕴含整条链相等 |
| **headroom** | 显示编码的上限，`1` 是 SDR；EDR 屏上可以大于 1 |
| **画面天花板（ceiling）** | S2 出口的画面亮度上限，默认 +2.3 EV（线性 4.925），0…+4 EV 可调；它和 headroom 管的事情不同：一个限制照片，一个限制屏幕 |
| **工作基色** | 线性 Rec.2020，所有线性域运算都在它里面做 |
| **OETF** | 光→信号的传递函数；S4 用 sRGB 分段函数，Display P3 共用同一条 |

## 与另外两份文档的分工

- `README.md`：项目是什么、怎么构建、门槛命令。它的管线表与本文同源，两边冲突时以代码为准。
- `docs/architecture-decisions.md`：**为什么**这样定、什么条件下这个决定会错、当时的实测证据。本文说「现在是什么」，那份说「凭什么」。
- 本文：把两者的结论组织成一份能从头读到尾的算法文档，并补上公式与开源对照。
