# 卷首：这份文档是什么

Photons 是一个 macOS 上的原生 RAW 工作流：导入一个文件夹、挑片、非破坏性显影、导出。它不自带解码器——去马赛克、镜头校正、机器学习降噪来自 Apple 的 `CIRAWFilter`（`Sources/PhotonsCore/RAWDecoder.swift:1`）。解码之上的整条算术链、蒙版、色彩管理、XMP 与导出，是 Photons 自己的 Metal 渲染图。

这份文档只讲解码之上的那一半：**画面如何被画到屏幕上、每个参数作用在哪个域、这些参数的具体算法**。

## α 阶段声明

项目仍在 α。本文描述的是**当前实现**，不是稳定 API，也不是路线图。管线阶段、参数范围、常数都会变；每一页页脚写着构建时的代码基准（`git rev-parse --short HEAD`），正文里的每个常数后面跟着 `文件:行`。当文档与代码冲突时，以代码为准，并把那一处当成文档的 bug。

不写的东西：界面设计（布局、控件、交互规格）、性能优化计划、与其他软件的评测。文中会出现「面板上的滑杆」这样的说法，那只是参数的名字，不是界面描述。

## 读者

- 想知道「这个滑杆到底动了什么」的高级用户；
- 要评审渲染正确性的工程师；
- 准备改这条管线的未来贡献者。

阅读前提：知道 RAW 是线性光、知道 sRGB 不是「颜色」而是传递函数、不害怕 `log2`。不要求读过 Photons 的代码。

## 三个域，先说清楚

后面每一章都围着这三个域转，这里先给一句话版本：

| 域 | 变量是什么 | 典型操作 | 在管线里的位置 |
|---|---|---|---|
| **RAW 解码域** | 相机原始像素，由 Apple 的 `RawCamera` 解释 | 去马赛克、色温/色调、机身降噪、镜头校正 | `CIRAWFilter`，渲染图之外 |
| **场景线性域** | 线性光，`1` 是 SDR 白，可以大于 1 | 黑电平、曝光、黑白端点、曲线、去雾、暗角 | S1 到 S1.9 |
| **显示参考域** | 经过色调映射的显示码，`0…1` | 高光/中间调/阴影、对比、饱和、HSL、分级、锐化、颗粒 | S2 之后 |

一条贯穿全文的规则：**一个操作必须待在它的量所在的域里**。把曝光做成显示域增益，就再也拿不回被压缩的高光；把去雾做成显示域减法，`A = 1` 会让高光越去雾越亮（`Sources/PhotonsCore/Stage.swift:55`）。第三、四章的大部分篇幅，都是在解释这句话的后果。

## 记法

| 记号 | 含义 |
|---|---|
| `EV` | 以 2 为底的对数曝光，`+1 EV` = 光量 ×2 |
| 显示码 | sRGB 编码后的 `0…255`，`0.5` 约为 18 % 灰的编码值 |
| `Y` | 工作基色（线性 Rec.2020）下的亮度，权重 `0.2627 / 0.6780 / 0.0593`（`Sources/PhotonsCore/ColorPrimaries.swift`） |
| `L` | `log2(Y)`，单位是「相对显示白的 EV」，显示白处 `L = 0` |
| `u` | 曲线的横轴坐标：`0…0.5` 是 SDR 显示码，`0.5…1` 是 `+0…+4 EV`（`Sources/PhotonsCore/HDRCurve.swift:46`） |
| `S0…S4` | 渲染阶段编号；`.5` / `.6` 之类是插在中间的阶段，执行顺序见第 1 章 |
| 键 / key | 阶段缓存的标识串，只由该阶段真正读到的参数组成（第 2.4 节） |

## 术语表

| 术语 | 在这份文档里的意思 |
|---|---|
| **画布（canvas）** | 屏幕上的那块像素面，尺寸等于 drawable 的像素尺寸；照片可以在里面留黑边 |
| **内容像素** | 裁剪后的照片自己的像素网格（`RenderOptions.scale` 作用在它上面） |
| **rung** | 解码阶梯上的一档，`0.5` 是预览档、`1.0` 是全分辨率档 |
| **stage** | 渲染图里的一个 pass，有独立的输入、输出与缓存键 |
| **条件 stage** | 只有谓词成立时才存在的阶段（有蒙版、曲线非恒等、颗粒 > 0……） |
| **中性零变化** | 没碰过的参数必须让像素逐字节不变，而不只是「看起来一样」 |
| **键链（key chain）** | 每个阶段的键 = `H(上一阶段的键 | 本阶段材料)`；链尾相等蕴含整条链相等 |
| **headroom** | 显示编码的上限，`1` 是 SDR；EDR 屏上可以大于 1 |
| **工作基色** | 线性 Rec.2020；所有线性域运算都在它里面做 |
| **OETF** | 光→信号的传递函数；S4 用 sRGB 分段函数，Display P3 共用同一条 |

## 与另外两份文档的分工

- `README.md`：项目是什么、怎么构建、门槛命令。它的管线一节是 M1 时点的摘要，个别归属已经被后续派单改过（例如黑白端点已从 S2 移到 S1），本文以代码为准。
- `docs/architecture-decisions.md`：**为什么**这样定、什么条件下这个决定会错、当时的实测证据。本文说「现在是什么」，那份说「凭什么」。
- 本文：把两者的结论组织成一份可从头读到尾的算法文档，并补上公式与开源对照。
