# 坐标空间术语规范（唯一语言）

> **为什么要这份文档**：旋转/裁切/透视的交界上，历史上每一类 bug 都是"同一个矩形被两处用不同取整算出来"
> （176 / 188 / 192 / 196 / 202 / 219 / 224 / 231 / 232 / 246）。代码已经把四个空间收进
> `Sources/PhotonsCore/CanvasSpaces.swift`，但**口头/规格里的用词一直是散的**（"画布"既指帧画布也指源画布，
> "原图"既指源像素也指整幅照片）。本文件规定唯一用词；写规格、写注释、写提交信息、口头讨论一律照此。
>
> 代码是判据：`CanvasSpaces.swift` 的四个 `var` 就是下面四个空间的真身。若本文件与代码冲突，以代码为准并回来改本文件。

## 1. 五个空间（编号固定，引用时写 `S1…S5` 或中文全名）

| 编号 | 中文（**唯一写法**） | 代码 | 定义 | 单位 / 归一化 |
|---|---|---|---|---|
| **S1** | **源像素**（source pixels） | `CropGeometry.source` | 解码得到的照片像素，已按 EXIF 摆正、**未**做透视/旋转/裁切 | 像素；`[0,1]²` 归一化时指整幅照片 |
| **S2** | **帧**（frame） | `frameSize` / `frameExtent` | 文档**保留**的那块画面（裁切框围出的那块），1:1 像素网格 | 像素 |
| **S3** | **帧画布**（frame canvas） | `canvas` | **301 起 = S2 本身**：旋转后的裁切框仍是 `W × H`，它就是渲染器输出、导出的图像 | 像素 |
| **S4** | **源画布**（source canvas） | `photoCanvas` | 把**整幅照片**（S1）旋转后包住它的轴对齐矩形。裁切框可以出照片（黑角），但**不可出源画布** | 像素；裁切钳制基准 |
| **S5** | **视口 / 窗口**（viewport / window） | `LoupeFraming.viewport`、窗口 rung | 屏幕上的可见区域（含 fit/zoom 缩放与相机位置） | 设备像素 |

> 命名变更（2026-11-02 用户定）：S3 曾叫"画布"、S4 曾叫"文档画布"，现统一为 **S3 帧画布 / S4 源画布**；
> 代码符号不变（`canvas` / `photoCanvas`），只是中文叫法改了。旧规格里出现的"画布"按本文映射。

铁律（来自代码，别口头改）：

- **301（方案 A，帧优先）**：`S3 = S2`。输出画布是旋转后的裁切框本身，不取 AABB；AABB 只留在 `S4`
  （以及裁切框的合法区）里。
- `S4` **只是** (S1, 角度, 四分之一转) 的函数 —— **永远不依赖** 缩放、窗口、视口、裁切框；这是"钳制与屏幕无关"的根。
- `S2 → S3` 是**恒等**；旋转在 `S0` 内部完成（canvas → source 的 `R(−θ)`），不再把帧旋进一块更大的画布。
  `CropGeometry.frameExtent` / `canvasInset` 仍是旧 AABB 读数的陈迹，不参与 301 的渲染路径。
- 两个模式**不各有一套空间**，只有"当前谁被画出来"不同（见 §3）。

## 2. 用户口语 → 规范用词（对照表）

| 口语 | 规范用词 | 说明 |
|---|---|---|
| 像素层 | **S1 源像素** | 只在说"修复/蒙版作用的原始像素"时才用它 |
| 裁切框 | **S2 帧** 的边界 | 框本身是 S2 的矩形，不是"画布" |
| 画布 | **S3 帧画布**（保留画面）/ **S4 源画布**（整幅照片） | **单独说"画布"是被禁止的**，必须带限定词 |
| 裁切前的画布 | **S4 源画布** | 它大，裁切框可以出它？不 —— 框不可出 S4 |
| 原图 / 全图 | **S1 源像素** 或 **S4 源画布**（看语境） | 禁止裸用"原图" |
| 屏幕 / 适应后的画面 | **S5 视口** | fit 90% 是 S3 装进 S5 的比例，不是 S1 的比例 |
| "画面偏左/偏上" | **S3 在 S5 里的位置** | 位置错永远先问：是 S3 算错，还是 S3→S5 的映射错 |

## 3. 两个模式里，谁被画、谁被钳

| | 编辑（非裁切） | 裁切界面 |
|---|---|---|
| 画出来的图像 | **S3 帧画布**（保留画面，90% 装进 S5） | **S4 源画布**（整幅照片，含旋转黑角） |
| 叠加的框 | 无 | **S2 帧** 的边界（可拖） |
| 钳制基准 | —— | 框不可出 **S4**（224/227）；框可出照片像素（S2 可小于 S1 的旋转区域） |
| "适应"基准 | **S3 装进 S5 的 90%**（259 后） | 同一套 90%（213；入口不再二次乘 0.9） |
| 修复 / 蒙版作用域 | **S1 源像素**（249 之后） | 同左（与界面模式无关） |

> 用户 2026-11-02 的原话就是这个模型的另一种说法：「非裁切界面像素层看起来=画布层，但实际上画布层有两个
> （一个恰好等于像素层，一个裁切前的）；进入裁切界面后，之前的像素层/画布层变为裁剪框，真正的画布层被加载，
> 顺带加载全部像素层。」—— 对应：**S3 与 S4 是两个画布**；进入裁切时画的是 S4、框是 S2、像素域是 S1。

## 4. 表述禁区（写规格/注释时一律不许出现）

1. 裸用"画布" → 必须写 **S3 帧画布** 或 **S4 源画布**。
2. 裸用"原图/全图" → 必须写 **S1 源像素** 或 **S4 源画布**。
3. 把"适应 90%"说成"画面缩到 90%"而不说清是 **S3 装进 S5**。
4. 用"AABB"代替具体空间名（AABB 只是构造手段；要写"**S4** 的 AABB"）。
5. 把裁切框说成"画布"；把 S5 的坐标说成"画布坐标"。
6. 说"两套逻辑" —— 只有**一套空间定义**，两种**呈现模式**（§3）。

## 5. 各 API 返回哪个空间（写代码时的查表）

| 调用 | 返回 | 空间 |
|---|---|---|
| `CropGeometry.source` | 摆正后的照片尺寸 | S1 |
| `CropGeometry.frameSize` | 保留画面的 1:1 像素尺寸 | S2 |
| `CropGeometry.frameExtent` | S2 旋转后的连续包围盒（301 起只是合法区读数，不是 S3） | S2 的 AABB，旧口径 |
| `CropGeometry.canvas` / `plan.canvas` | 渲染输出尺寸（= `frameSize`） | S3 = S2 |
| `CropGeometry.photoCanvas` | 整幅照片旋转后的包围盒 | S4 |
| `LoupeFraming.mapping` | S3 → S5 的映射（origin/content 都是 S5 里的位置） | S3→S5 |
| `session.ingestedSourceFrame` | 解码期发布的整份文件尺寸（已除 `decodeScale`） | S1 |

## 7. 一句话记住

> 修复/蒙版在 **S1 源像素**；裁切框是 **S2 帧**；编辑界面画的是 **S3 帧画布**；裁切界面画的是 **S4 源画布**；两个都装进 **S5 视口**。
