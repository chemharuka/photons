# Mac / iPad 并行开发建议

状态：**建议性设计记录，不是强制规则，也不是 AGENTS.md**。更新日期：2026-11-16。

这份文档帮助人和 agent 理解当前方向，不要求未来任务机械执行。用户的新要求、维护者的新决定和经过验证的技术事实可以改变下面任何建议。策略变化时，建议同时修改本文或标注哪些段落已经过时；不要因为旧文档存在而继续实施已经不适用的方案，也不要把本文当成额外的审批要求。

## 当前目标和阶段

Mac 是主要交付版本；iPadOS 是验证共享引擎、LCC、全景和触控工作流的开发预览。长期目标是两端都有完整功能，主要差别是布局和系统交互。当前覆盖范围见 [iPad 开发预览](ipad-preview.md)，不能把长期目标理解成已经实现了功能对等。

创建 iPad target 不等于每次 Mac build 都必须构建、发布 iPad。实验阶段可以独立发布、分阶段补齐界面，不建议仅因为 iPad 尚未完成某个界面就阻塞 Mac 的正常更新。将来两端成熟后，再决定是否把双端验证变成发布条件。

## 倾向采用的架构

- 一个仓库，共享 Swift packages，Mac 和 iPad 各有应用入口。避免通过复制整个仓库或长期维护两套算法来移植。
- 图像处理、参数语义、历史快照、元数据、预设、LCC、拼接和编码尽量共用。平台层主要处理窗口、触控、文件授权、通知、后台执行和屏幕能力。
- 可共享的控件内容和参数定义逐步共享；没有必要为了达到某个代码复用百分比，先重写全部 Mac 界面。
- 算法和导出行为不写进某个平台的 View。相同输入、参数和处理版本应具有相同含义；跨 OS/GPU 的验证采用合理误差，不能普遍承诺逐字节相同。
- 编辑数据兼容与照片库云同步是两个问题。共用 SQLite/JSON 并不意味着已有跨设备同步；文件授权书签也不能当作跨设备访问凭证。

当前已经共享 `PhotonsCore`、`PhotonsCatalog`、`PhotonsPanorama`、`PhotonsExport` 等模块。`DevelopControls` 提供两端共同使用的部分检查器参数定义；`ImageSourceDecoder` 提供共同的普通图像入口。`PhotonsMobile` 暂时承担 iPad 状态与执行适配，尚未声称所有 Mac 状态控制器都已经跨平台。

## 新功能可以怎样处理

| 改动 | 实验阶段建议 |
|---|---|
| 共享算法或模型 | 修改一处；检查平台 API 和序列化兼容，尽量验证两端 |
| 共享参数 | 优先扩展共享定义，再检查两个界面的入口和布局 |
| Mac 窗口、菜单、Finder 行为 | 可以只修改 Mac 实现 |
| iPad 触控、Files、后台行为 | 可以只修改 iPad 实现 |
| 暂时无法移植的能力 | 说明未支持范围和后续方向，不用无效按钮冒充已实现 |
| 正式版本发布 | 按产品阶段分别决定时间，不承诺 Apple 审核同时完成 |

如果一个任务只授权修改单端，不要把这份建议扩大成未经请求的大规模双端重构。必要时在变更说明中记录另一端的影响即可。

## 布局与交互方向

截至本次记录，iPad 的用户偏好为：

- 左侧素材浏览是可隐藏边栏。
- 网格用双指缩放调整缩略图大小，不显示尺寸滑块；缩略图完整显示、保留长宽比。
- 单点照片显示右侧信息/检查器，再次单点同一张折叠；窄窗口可改为可关闭的检查器面板。
- 长按进入多选；选择至少两张后才显示全景入口。
- 顶部工作区放工具栏，右上角独立设置按钮，支持 Control-comma；Mac 原有 Command-comma 保持原平台行为。
- 拼接使用全屏工作区，进入前选择移轴接片或透视接片，两种入口应对应实际的配准方式。移轴模式：预览与机身行程/画幅示意图并列；画幅可拖拽，变动作为毫米位置约束重新配准，不把示意图拖动冒充已经成功拼接。
- 设置采用全屏标签页，通用、照片库与镜头配置分开，给后续 LCC 标定留出布局空间。
- 星级和旋转放右侧检查器。只保留网格和单图，使用井字形和矩形图标，不使用胶片条。

这些是当前设计偏好；未来用户修订时应随之调整，不应被本文件冻结。

## 性能和系统边界

- 大幅 RAW / 全景首先考虑预览尺度、缓存、分块、内存预算、取消与热状态，避免简单地提高并发。
- Mac 子进程和 iPad 应用内异步任务不是同一种隔离。iPad 后台执行需要系统支持，不能把异步 Task 等同于无限后台运行或崩溃隔离。
- 共享 `PhotonsExtensions` 的纯文件处理代码可以复用，但现有可执行降噪/HDR 助手不能直接在 iPad 启动。替代实现、授权和分发方案需根据当时情况选择；独立模块名称本身不构成 GPL 许可隔离的结论。
- HDR 数据和 HDR 屏幕呈现分开；设备不支持某种显示/后台资源时，明确降级原因，尽量保留文档和输出能力。

## 验证建议

建议每个变更按实际影响选择检查：共享单元测试、Mac 构建、iPad 模拟器构建、典型照片流程、真机内存/色彩/后台验证。仓库的 iPad 检查脚本可以独立运行，不是强制要求所有 Mac build 都通过 iPad 发布门槛。

模拟器成功不代表真机的 `.3FR` 支持、HDR 屏幕、能耗和 200 MP 全景已经验证。记录实际设备、系统、输入、输出尺寸与结果；把“已接入”“测试通过”“尚未测试”分开描述。不要把一次实验结果升级成永远有效的策略。
